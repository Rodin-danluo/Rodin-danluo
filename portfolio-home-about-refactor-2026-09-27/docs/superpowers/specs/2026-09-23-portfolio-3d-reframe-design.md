# Rodin 个人作品集 3D 重构设计说明

日期：2026-09-23

## 1. 项目目标

将现有网站从“偏产品设计师的动态作品集”重构为兼容两条求职方向的个人作品集：

- 产品经理：突出问题定义、策略判断、数据意识、推进与交付。
- 用户体验设计师：突出用户洞察、信息架构、交互设计与体验表达。

首页的唯一任务，是让招聘者在十秒内理解：罗丹是谁、擅长解决什么问题、有哪些真实项目可以证明。

## 2. 设计原则

本次重构吸收高星个人网站的结构方法，但不复制任何站点的代码、模型或专有视觉资产：

- 借鉴 Brittany Chiang：首屏定位清楚，项目按职责与结果组织。
- 借鉴 Craftz.dog：只设置一个招牌 3D 视觉，其他界面保持克制。
- 借鉴 David Heckhoff：3D 场景承担身份与氛围，项目区回到高效的二维内容浏览。
- 借鉴 Brian Lovin：把真实项目组织成长期可维护的个人项目目录。
- 保留 Bruno Simon 式实验入口，但不让实验性交互成为唯一导航。

不采用“整站游戏化”“模拟操作系统”“每个区块一种动画”的方案。这些方案展示技术多于展示罗丹本人，也会降低招聘者的信息获取效率。

## 3. 核心视觉概念：Rodin Product Studio

首页的招牌元素是一张可交互的 3D 产品工作台。它不是通用办公桌，而是由罗丹真实项目中的物件组成：

- 放大镜与信号点：用户研究、搜索意图与问题诊断。
- 流程卡片与连接线：产品策略、信息架构和 UX Flow。
- 手机原型：界面与交互落地。
- XML 单据、地图标记、AI Agent 光球、照护连接节点：四个精选项目的个人化线索。

场景通过滚动完成一次明确的叙事：零散信号进入工作台，逐步被组织成流程与原型，最后成为可交付产品。3D 动画只讲这一件事——“从复杂问题中找到信号，并把判断做成可用体验”。

不制作卡通人物，也不复制 David Heckhoff 的房间。这样既保留亲和的 3D 材质，又能建立属于罗丹自己的视觉资产。

## 4. 品牌与视觉系统

### 色彩

- Studio Paper `#F2F0EA`：主背景，保持作品阅读舒适。
- Blueprint Blue `#2F5BFF`：产品结构、交互状态和主要 CTA。
- Model Clay `#F36F56`：工业设计模型感，用于关键 3D 物件。
- Signal Mint `#BCECCB`：洞察、数据与有效状态。
- Graphite `#17191D`：正文和结构线。

避免继续使用大面积桃橙渐变，也避免“深色背景 + 荧光绿”的常见 AI 网站组合。

### 字体

- 展示与正文：现有 TikTok Sans。
- 数据、标签与元信息：现有 Geist Mono / Departure Mono。
- 不新增远程字体依赖，保证 GitHub Pages 加载稳定。

### 形态

- 3D 物件使用黏土、磨砂塑料、纸张和半透明亚克力材质，呼应工业设计背景。
- 二维界面使用清晰栅格、窄边框和留白，不使用大面积玻璃拟态。
- 圆角只用于真实“卡片、设备、按钮”对象，不作为全站装饰。

## 5. 页面结构

```text
固定导航
├── Work
├── About
├── Lab
└── Contact / Resume

Hero：一句定位 + 两个行动入口 + 3D Product Studio
↓
Selected Work：四个精选深度案例
↓
About：双能力叙事 + 真实成果 + 经历时间线
↓
Lab：AI Demo、个人实验、3D Project Archive
↓
Contact：求职状态、联系方式、简历下载
```

### Hero

- 身份标签：`PRODUCT MANAGER × UX DESIGNER`。
- 主标题：表达“发现问题并塑造体验”，不再使用 `AI Product Designer` 作为唯一身份。
- 简介：工业设计背景，擅长从用户信号与业务问题出发，推进产品定义、体验设计和快速验证。
- CTA：`查看精选项目`、`下载简历`。
- 右侧为唯一主 3D 场景，文字始终由 HTML 承载，保证 SEO 和可读性。

### Selected Work

- 延续当前未提交改动中的四个精选案例和两列布局。
- 案例顺序：研狐 AI Agent、小匠行、XML 发票助手、e家护。
- 每张卡片优先展示问题、个人角色、关键动作和结果，不把技术栈放在视觉首位。
- 桌面端两列，移动端单列，不提供轮盘切换。

### About

- 不按“产品能力 / 设计能力”把人割裂成两半。
- 用统一流程组织：发现问题 → 定义策略 → 设计体验 → 推进落地。
- 现有成果数据与工作经历保留，但减少同义标签与装饰性状态组件。

### Lab

- 保留 StyleSwap、临场应变等实验。
- 将 `project-wheel.html` 作为 `3D Project Archive` 独立实验入口。
- 轮盘不再通过 iframe 嵌入首页，也不与项目卡片形成重复导航。

### Contact

- 保留求职状态、邮箱、微信和简历下载。
- 3D 工作台在页面结尾进入“完成交付”的收束状态，但不遮挡联系方式。
- 暂不保留伪造的访客留言示例；若留言不能真实持久化，则改为静态合作邀请或移除。

## 6. 交互与动效

- 鼠标移动：只影响 3D 工作台的轻微视差，不控制页面核心导航。
- 页面滚动：控制场景中物件的组织过程，不锁定滚动、不制造长时间 pinned section。
- 项目卡片：使用轻微位移和图片缩放，不继续使用大角度 3D tilt。
- 导航：滚动到不同区块时更新当前状态，点击使用原生锚点。
- 不自动播放声音；不加入背景音乐。
- `prefers-reduced-motion` 下停止循环动画，显示稳定的工作台构图。

## 7. 技术方案

- 保持静态 GitHub Pages，不迁移 React、Vue 或构建工具。
- 使用官方 Three.js ES Module 的固定版本，并本地化到 `assets/vendor/`，避免运行时依赖远程 CDN。
- 新增独立场景脚本，例如 `assets/js/rodin-studio.js`，不继续把所有逻辑塞入 `index.html`。
- 场景优先使用 Three.js 基础几何体与 CanvasTexture，不引入大型 GLTF 模型和 Blender 工作流。
- 保留 `projects.json` 作为项目数据源。
- 删除首页轮盘 iframe 和对应事件桥接代码；保留独立 `project-wheel.html`。

## 8. 性能、兼容与降级

- 设备像素比上限设为 1.5–1.75。
- 页面不可见时暂停渲染；场景离开相关区域后降低或停止更新。
- 首屏 Three.js 文件与首页内容并行加载，不用假进度条阻塞正文。
- WebGL 不可用或脚本加载失败时显示 CSS 静态工作台背景，文字、项目和导航必须仍可使用。
- 移动端降低物件数量与阴影复杂度，不要求拖拽操作。
- 所有核心链接、按钮和项目卡片保持键盘可操作。

## 9. 错误与边界处理

- `projects.json` 加载失败时展示明确的重试提示，并保留至少一个静态联系入口。
- 简历文件不存在时不展示失效下载按钮。
- 外部 Demo 使用新标签页并设置 `noopener noreferrer`。
- 不在 3D Canvas 内承载必须阅读的文字或唯一可点击入口。

## 10. 验收标准

- 首屏不再将罗丹唯一定位为 AI Product Designer。
- 首页不再出现轮盘切换或轮盘 iframe。
- 四个精选案例在桌面端两列、移动端单列且可正常打开。
- Three.js 场景在桌面端可见并响应轻微视差；移动端和减弱动效模式有稳定降级。
- 禁用 JavaScript 后仍能阅读定位、项目基本信息与联系方式。
- Lighthouse 或等价检查中不出现由 Canvas 导致的严重布局偏移。
- 现有 Playwright 测试继续通过，并补充 3D 容器、降级状态、导航与 Lab 轮盘入口测试。

## 11. 本次范围外

- 不重做三个完整项目详情页。
- 不新建博客、订阅或内容后台。
- 不制作写实人物模型或复杂 Blender 场景。
- 不上线真实留言数据库。
- 不在本轮重新设计简历内容，但会校验网站简历链接是否有效。
